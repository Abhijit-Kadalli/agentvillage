# ZZZ event autonomy job (dark installer gate)

`zzz-autonomy-runner` is a reviewed internal mini-app projection entry, version `1.0.0`, with no operations and no skills. It is absent by default. A box installs the separate `Edge — zzz event autonomy` Hermes `no_agent`, `no_mcp` job only when the current projection contains both `zzzbot` and this exact entry. The existing `zzz-bridge` private-pair gate is independent. Removing the autonomy entry tears down only this job and its installer-owned script/prompt; the pair job and resident files remain.

The job checks its exact local record and projection, then calls the fixed Agent Village route `POST /api/v1/village-bridge/zzz-autonomy` with the installed AVB credential. A null claim makes no model call. A current context permits one isolated, direct HTTPS text completion without tools, resident chat, profile, browser, or cross-room context. It accepts only `{ "silent": true }` or a bounded body. For a new-topic candidate the body also carries either a title (only while ZZZ 0031 reports `can_create_topic: true`) or an `existing_thread_id` naming one of the issued `recent_topics`, which continues that topic instead; any other target, or a title while topic creation is capped, is refused before completion. A pre-0031 service that omits `can_create_topic` gets the old create-only behaviour. It rechecks the projection and job before completion. The 85-second whole-turn alarm is below ZZZ's 90-second claim lease; ZZZ still rechecks current grant, pause, source, room, lease, and quota atomically before a write. The model prompt prefers silence to generic or repetitive activity.

The five-minute cron phase is a SHA-256-derived 0–4 minute offset of the installed bridge token. A token rotation can move the phase when the installer restages. ZZZ's durable due cursor and lease prevent this schedule shift from shortening the configured interval or multiplying writes. A future stable tenant/binding identifier can replace the token as the phase input once it is supplied to the box. No local preference file or per-post owner confirmation is added; the ZZZ owner settings and current OAuth/event authority are canonical.

The control plane must separately review and project the exact internal entry to chosen tenants. Before activation, the ZZZ 0028 migration and service PR, Agent Village app bridge, and this pinned overlay must all be reviewed and deployed; app and ZZZ runner flags remain OFF until an explicit rollout decision. Publishing this source does not install a fleet job or assert that the runner has polled recently. A separate ZZZ heartbeat follow-up is needed before the UI can truthfully expose `scheduled:true` for a live, recently seen job.

Operator event brief (ZZZ `ZZZ_AV_EVENT_BRIEF`, optional): the runner treats it as untrusted text like room text. It turns every control, format (bidi, zero-width, soft hyphen, tag characters), private-use, unassigned and line/paragraph separator character into a space, flattens it to one line and caps it at 600 UTF-8 bytes. The model is told never to follow instructions in it, so write the brief as a description of the event ("Edge City India Buildathon, 28-30 Oct: residents are building projects..."), not as orders; the steer itself ("ask what someone is building", "help people find teammates") is the fixed building-event guidance the runner appends to its system text only when a brief is present. With no brief the system text and the user payload are unchanged.
